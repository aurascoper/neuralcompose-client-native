# Acceptance record — M6: native audio lifecycle (2026-07-28)

Branch `m6/native-audio-lifecycle` from `main @ 1dae503`. Audio I/O stays
platform-native (AVAudioSession/AVAudioRecorder/AVAudioPlayer on iOS;
MediaRecorder/MediaPlayer on Android); Rust owns only the deterministic
lifecycle state machine and the portable recording manifest. Acceptance
baseline: the Expo-oracle behaviors observed for PR #45 gates 2/3/5.

## Core (Rust)

`src/audio.rs`: `RecordingPhase` {Idle, PermissionDenied, Ready, Recording,
Persisting, Recorded, Playing, Interrupted, Failed{reason}} with legal-
transition enforcement, complete ordered transition history, and
`RecordingManifest` {id, created_at_ms, duration_ms, format, byte_size,
sha256_hex}. Manifests appear ONLY on successful persist (atomicity);
invalid events are rejected no-ops; `with_manifests()` reloads entries at
Idle (never a phantom state); `sha256_hex()` is the portable content hash
(NIST vector pinned). **12 contract tests** green under both feature sets;
whole-workspace suite 58 tests; clippy `-D warnings` + fmt clean.

## Cross-language bindings

Swift (iPhone 17 sim XCTest) 3/3 and Kotlin (host-JVM JNA) 3/3, each running
a denied→granted→record→persist→play→restart pass through the regenerated
UniFFI bindings.

## Review-response addendum (2026-07-28, blocking findings resolved)

1. **Atomic persistence**: both shells now run the full transaction —
   stop+close → bytes → size+sha → CANDIDATE manifest list → same-directory
   `.partial` write (fsync on Android; atomic replace on iOS) → atomic
   rename over canonical → only then `on_persisted`. Any failure before the
   rename leaves the previous canonical file intact, reports
   `persist_failed` (no manifest), and deletes the orphan audio bytes.
2. **Playback independent of permission**: `on_play_start` is legal from
   Idle/PermissionDenied/Ready/Recorded when a manifest exists; a private
   `playback_return_phase` returns exactly to the origin (public phase set
   unchanged) — including across interruptions. Four new Rust regressions.
   **Device-proven**: with permission revoked (`user-fixed`), `PLAYING` ran
   over 3 reloaded entries and completed back to `PERMISSION DENIED` with
   Record still disabled (screenshots r3–r5).
3. **Corruption visible**: malformed canonical JSON is quarantined
   (`recording-manifests.corrupt-<ts>.json`) with a red banner naming the
   preserved file and stating recordings were not deleted; per-entry
   integrity (exists + byte size + sha256) marks failures NOT PLAYABLE with
   a visible label. **Failure injection performed on the Pixel**: garbage
   written over the canonical manifest via `run-as` → relaunch showed the
   quarantine banner, the quarantined file existed on disk, and
   `recordings/*.m4a` were untouched (screenshot r6, `ls` evidence).
4. **Transition-history claim corrected**: transition history is
   **process-local** (in `AudioSnapshot`), intentionally reset per process;
   the portable `RecordingManifest` carries id/created/duration/format/
   size/hash only. Earlier wording claiming manifests carry transition
   history was wrong and is corrected here and in the PR body.

Operator rerun sequence executed on the review-fix build: persist (new
entry with real hash) → restart (entries reloaded, no phantom) →
permission denied → play (origin-preserving). Rust 62 tests, Kotlin 3/3,
Swift 3/3, iOS build succeeded.

## Findings / follow-ups

1. **Contract refinement proposed (not silently changed):** after restart,
   `play_start` is unreachable until a new recording (it requires the
   `Recorded` phase; a fresh process with reloaded manifests sits at
   `Ready`). Proposal for review: allow `play_start` from `Ready` when
   manifests are non-empty.
2. Stale jniLibs bite: rebuilding bindings without re-running `cargo ndk`
   produced `UnsatisfiedLinkError` on-device. `scripts/gen-bindings.sh` and
   the README now need a reminder that Android `.so` and Kotlin bindings
   must regenerate together (the .so is not committed).
3. Interruption paths are implemented on both shells but not device-
   exercised this session (no incoming-call simulation performed).
