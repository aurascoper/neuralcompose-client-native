## Findings fixed during acceptance

Three defects were found by the gates themselves, not by inspection.

1. **Misleading selection failure** (found by the Swift binding test). When
   several candidates failed for different reasons, `select_runtime_variant`
   reported the *last-examined* failure, so an incidental uninstalled
   backend masked the actionable "this backend cannot do structured
   output". Selection now reports the furthest-progressed failure, pinned by
   `the_furthest_progressed_failure_is_reported` and by the Swift assertion
   that caught it.
2. **Windows-invalid schema base URI** (found by CI on both Windows
   runners). The golden test built a `file://` base from a canonicalized
   path; Windows yields an extended-length `\\?\D:\...` path that is not a
   valid URI. Sibling `$ref` resolution now uses an in-memory
   `jsonschema::Resource` under a synthetic base URI, so no filesystem path
   becomes a URI on any platform.
3. **Non-portable binding-drift gate** (found by CI on Linux). Two problems:
   `gen-bindings.sh` hardcoded `.dylib`, and the drift script compared
   against a temp copy of untracked `ios/Generated/` while swallowing the
   copy failure with `|| true`. The extension is now selected per platform,
   and the gate asks git whether the *tracked* artifacts moved after a fresh
   regeneration plus the wrapper copy.

## Review amendments (PR #3 round 1)

Four blocking contract findings, all resolved as compact amendments:

1. **Workload absent from selection** — `RequiredCapabilities` gains
   `generation`/`embeddings`; an embedding-only backend can no longer be
   selected to generate. Pinned by
   `an_embedding_only_backend_is_never_selected_for_generation` plus Swift
   and Kotlin assertions.
2. **Same-backend variants chosen by name order** — `AnySupported` and an
   explicit backend both fail with `AmbiguousVariantsForBackend`;
   `BackendRequirement::ExplicitVariant` is the only disambiguator. Pinned by
   `two_variants_of_one_backend_must_be_named_explicitly` plus both shells.
3. **Contract identity asserted, not sealed** — the digest now excludes the
   caller-supplied label, a policy is valid only when its id *is* that seal,
   variant ids must be 64-hex seals, and `variant_binds_to_contract` binds a
   variant to a measured policy. Pinned by
   `contract_identity_is_sealed_by_its_terms` and by a golden test asserting
   the frozen variant carries the frozen policy's seal.
4. **Both tolerances always required** — tolerances are now `Option` with at
   least one declared; out-of-scope measurements surface as
   `MeasurementOutOfScope`. A second frozen fixture
   (`valid-embedding-conformance-policy.json`) is an embedding-only contract
   with no logits tolerance. Pinned by
   `measurement_scope_follows_the_contract_kind`.
