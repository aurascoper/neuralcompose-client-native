## Finding fixed during acceptance

The Swift binding test caught that when several candidates failed for
different reasons, `select_runtime_variant` reported the *last-examined*
failure — so an incidental uninstalled backend masked the actionable
"this backend cannot do structured output". Selection now reports the
furthest-progressed failure, pinned by
`the_furthest_progressed_failure_is_reported` in Rust and by the Swift
capability assertion.

## Non-claims

- **No model executed.** No weights were downloaded, loaded, or run.
- **No accelerator library was linked.** CUDA, Vulkan, OpenVINO, QNN, ROCm,
  and Core ML appear only as configuration strings in fixtures.
- **No target is supported.** Every support-matrix row is `Contracted`; no
  row reached `BuildValidated` or beyond under these contracts.
- **No backend equivalence is claimed.** Conformance verdicts are defined,
  not measured — no backend has been observed.
- **No provider SDK, Tauri application, or desktop packaging** is present.
- **No physical hardware evidence** was produced; the simulator/JVM results
  above are binding-level contract tests, not device acceptance.
