## Known caveat → first corrective milestone (M5-A)

**Inherited receive-time across reconnects.** The monitor keeps
`last_received_at_ms` across socket generations within one subscription, so
immediately after a reconnect it can briefly report `Live` on the strength of
a sample received on the PREVIOUS socket. This matches the Expo oracle
(`useEEGStream`'s `lastUpdate` survives `LiveApiClient`'s internal
reconnects) and is characterization-tested as v0 behavior — but it is the
same category of error Gate 4 exposed: transport state from one connection
used as evidence about another.

Planned contract revision (M5-A, before the Compose shell):

```
socket N receives sample   → Live
socket N closes            → Closed
socket N+1 opens           → OpenNoData
socket N+1 receives sample → Live
```

with `connection_generation`, `received_on_current_connection`, and separate
`last_received_at_{any,current}_connection`. Cached traces may stay visible,
but must not authorize `Live` for a new socket. The same boundary governs
retry reset: an open-immediately-close server currently resets the attempt
budget on every handshake (`Opened` → `attempts = 0`), permitting infinite
retries; M5-A resets the budget on the first ACCEPTED frame (or a defined
stable-open interval), not on handshake.
